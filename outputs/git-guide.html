Git 实战流程指南

从零配置 → 日常开发 → 分支协作 → 上线发布，一套流程走通

本机 Git 2.55.0已安装 Windows 阅读约 10 分钟

1首次配置（只做一次）

你的机器上 Git 已装好，但 身份信息还没配，现在不配的话第一次提交会直接报错。打开终端（PowerShell / Git Bash 都行）执行：

git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"

# 让新仓库默认分支叫 main（现在的主流习惯）
git config --global init.defaultBranch main

# 让终端显示彩色输出
git config --global color.ui auto
验证：git config --list --global 能看到刚才填的姓名和邮箱就成了。
关于用户名和邮箱：邮箱要用你在 GitHub/GitLab/Gitee 注册的那个，否则提交记录关联不到账号；用私人邮箱也行（GitHub 提供 noreply 邮箱用于保护隐私）。名字可以随便起，但建议用真实姓名，方便团队识别。

2理解三个区（最重要的一步）

Git 的所有操作都围绕这张图转，理解它就不会出乱子：

区域含义常用命令
工作区
Working Directory		你正在编辑的真实文件，随便改、随便删git status 看变化
暂存区
Staging Area		你「决定要提交」的快照，像购物车git add 放入 / git restore --staged 取出
本地仓库
Repository		已保存的历史版本，本地数据库git commit 存档
远程仓库
Remote		云端/服务器上的共享副本git push / git pull
一句话记忆：改代码 → add（放进购物车）→ commit（结账存档）→ push（上传云端）。

3日常开发主流程

这是你每天 90% 的时间会用到的循环，记住这6 条命令就够用了。

# ① 拉取同事的最新代码（每天开工第一件事）
git pull

# ② 查看当前状态：哪些改了、哪些在暂存区
git status

# ③ 把改动加入暂存区
git add .                  # 全部加入
git add src/login.js       # 或只加指定文件
git add -p                 # 逐块挑选（推荐：只提交想提交的部分）

# ④ 提交存档（写清楚为什么改，不要只写"update"）
git commit -m "fix: 修复登录页密码错误时未提示的问题"

# ⑤ 上传到远程
git push

# ⑥ 有冲突或想撤销时用
git status                 # 先看状态

提交信息怎么写

前缀含义示例
feat新功能feat: 增加密码重置功能
fix修Bugfix: 修复移动端菜单遮挡问题
docs文档docs: 更新 API 接口说明
style代码格式（不改逻辑）style: 统一使用 2空格缩进
refactor重构（既非新功能也非修 bug）refactor: 拆分用户服务模块
chore杂务（依赖、配置）chore: 升级依赖版本
撤销三兄弟（按你想撤销到什么程度选）：
git restore 文件 丢弃工作区改动（不可恢复，慎用）
git restore --staged 文件 从暂存区撤回，但改动还在
git commit --amend 改上一次提交的信息或内容

4分支流程（多人协作必学）

分支是Git 的核心价值：让每个人在互不干扰的"平行宇宙"里开发，最后合并。

① 建分支git switch -c feature/login从当前 main 拉出新分支去做功能
② 反复提交git add . && git commit -m "..."在自己的分支上正常提交
③ 同步主分支git fetch origin && git rebase main把别人的改动接进来，保持历史干净
④ 推送分支git push -u origin feature/login推到云端，提 PR 请求合并
# 常用分支命令速查
git branch                    # 列出本地分支
git branch -a                 # 列出所有分支（含远程）
git switch feature/login      # 切换到已有分支
git switch -c feature/new    # 创建并立即切换到新分支
git branch -d old-branch     # 删除已合并的分支
git merge feature/login      # 把某分支合并到当前分支
git rebase main               # 把当前分支的提交"搬"到 main 最新状态之后
merge 还是 rebase？规则很简单：公开共享的分支用 merge，自己的私有分支用 rebase。rebase 会改写提交历史，团队共用分支上乱用会让别人的提交凭空消失。

5连接远程仓库（GitHub / Gitee）

方式 A：HTTPS（最简单，推荐新手）

# 已有本地项目，关联远程仓库
git remote add origin https://github.com/你的用户名/仓库名.git
git remote -v                # 查看关联情况

# 首次推送（-u 建立追踪关系，以后直接 git push）
git push -u origin main

# 之后日常就是
git pull                    # = fetch + merge
git push
GitHub 从 2021 年起不再接受密码认证，需要用个人访问令牌（PAT）代替密码。GitHub 右上头像 → Settings → Developer settings → Personal access tokens → 生成，勾选 repo 权限。粘贴时终端不会显示任何字符，是正常的。

方式 B：SSH（一次配置，长期免密）

# 1. 生成密钥对（一路回车用默认值即可）
ssh-keygen -t ed25519 -C "你的邮箱@example.com"

# 2. 复制公钥内容，粘贴到 GitHub → Settings → SSH and GPG keys → New SSH key
clip < ~/.ssh/id_ed25519.pub

# 3. 测试连接
ssh -T git@github.com          # GitHub 成功会显示 "Hi 用户名!"

# 4. 之后用 SSH 地址克隆
git clone git@github.com:你的用户名/仓库名.git

6完整实战：从零到提交

第一次做项目时，照着这串命令走一遍就全通了：

# 场景：新建一个项目并推到 GitHub

# 1. 创建本地项目目录
mkdir my-project && cd my-project

# 2. 初始化 Git 仓库
git init

# 3. 创建 .gitignore（重要：告诉 Git 哪些文件不要管）
# Windows 下手动建一个名为 .gitignore 的文件，内容例如：
#   node_modules/
#   .env
#   dist/
#   .DS_Store

# 4. 写点代码，然后一次性加入并提交
git add .
git commit -m "chore: 项目初始化"

# 5. 在 GitHub 网页上新建一个空仓库（不要勾选 README），复制它的地址

# 6. 关联并推送
git remote add origin https://github.com/你的用户名/my-project.git
git branch -M main
git push -u origin main
clone 别人的项目：git clone 仓库地址 会自动下载代码并建立关联，直接进目录就能干活，不需要第6 步。

7常见状况处理

推送被拒绝（rejected）

git pull --rebase origin main
git push
原因：远程有你本地没有的提交。先拉下来接上再推。

合并冲突（conflict）

# 冲突文件中会出现 <<<<<<< HEAD ======= >>>>>>> 三段标记
# 手动编辑决定保留哪段内容，删掉标记后：
git add 冲突文件
git commit -m "merge: 解决冲突"

# 中途想放弃这次合并：
git merge --abort

误提交了不该提交的文件

# 还没 push 时补救：撤销上一次提交，保留文件改动
git reset --soft HEAD~1

# 已经 push 了：用 revert 生成一个反向提交（最安全，历史不消失）
git revert 提交哈希
谨慎使用：git reset --hard 会永久丢弃未提交的改动，无法恢复；reset --hard 到已推送的提交会让团队其他人崩溃。执行前先 git log --oneline -5 确认位置。

查看历史

git log --oneline --graph --all --decorate   # 图形化分支历史，最常用
git log -p 文件名                            # 看某个文件的具体改动
git blame 文件名                             # 逐行看是谁改的
git reflog                                   # 找回"消失"的提交（救命用）

9推荐的后续学习

  • 优先级最高：写好 .gitignore。密码、密钥、node_modules 一旦提交进历史就很难彻底清除。
  • 学交互式变基（git rebase -i HEAD~5）整理提交历史，PR 评审体验会好很多。
  • 了解 .gitignore 模板：GitHub 官方有涵盖各语言的模板库，直接抄。
  • GitHub Flow：建分支 → 提PR → 评审 → 合并 → 删分支，团队协作的事实标准。
